# 链影寻踪 scx 版本更新说明

本文档记录 `scx` 分支本轮集中优化的内容，并以当前代码实现为准。更新目标是把原有展示型原型进一步完善为可运行、可上传、可分析、可追溯的网络风险调查平台，同时突出以下三项核心创新：

1. 面向当前事件的多尺度上下文主动检索机制；
2. 跨时间窗口的长周期攻击链关联机制；
3. 跨源日志语义统一与实体关系联合建模。

## 一、更新后的系统定位

链影寻踪面向 Syslog、WAF、DNS、主机审计和 Windows 事件等多源安全日志，围绕以下调查闭环组织产品能力：

```text
事件流 → M0-M6 检测 → 风险发现 → 实体关联 → 案件攻击链 → 证据核验 → 分析员决策
```

当前版本同时支持：

- 约 4.6 万条受控事件流的检索、筛选和跨时间窗口展示；
- LOG、TXT、JSON、JSONL、CSV 小文件的真实上传；
- 上传文件经过后端 M0-M6 链路处理并持久化；
- 风险发现、实体、证据和案件在前后端之间联动；
- 小影智能体基于项目知识库和调查上下文进行分析；
- 评测口径与检测链路隔离，真实标签只用于评测。

## 三、本轮主要更新

### 1. 完整的小文件后端接入链路

数据源页面不再只模拟上传进度。文件会真实发送到 FastAPI，并执行可解释的 M0-M6 处理流程。

| 阶段 | 当前版本实际执行内容 |
|---|---|
| M0 | Drain 风格模板解析、源行号和原始日志引用 |
| M1 | 行为与结果语义归一、弱监督风险信号 |
| M2 | 用户、主机、进程、IP 实体抽取与规范化 |
| M3 | 实体图上下文、关系数量和新颖度 |
| M4 | 无监督模板稀有度与失败上下文异常 |
| M5 | 共享实体的前序风险事件与长周期关联 |
| M6 | 多模块可解释加权融合，生成发现和候选案件 |

处理结果持久化在：

```text
run_state/wad_ingestion.db
```

每条上传事件保存：

- `module_scores.M0` 至 `module_scores.M6`；
- 原始日志引用与源文件行号；
- 用户、主机、进程和 IP 等解析实体；
- 弱监督与无监督风险依据；
- 关联 Finding 与候选 Investigation；
- `labels_used=false`，明确检测过程不读取真实标签。

### 2. 统一事件流

受控数据和用户导入文件统一进入“事件流”产品视图：

- `Short`：`stream://short`；
- `Long`：`stream://long`；
- 上传文件：`stream://文件名`；
- 数据源类型统一显示为“事件流”；
- 已写入数据库的旧来源字段会在 API 和前端展示层自动归一；
- 内部仍保留数据血缘，供复现和审计使用。

这一调整消除了不同数据入口在日志检索、发现、案件和数据源页面中的割裂感，但不会改变原始日志内容或证据引用。

### 3. 多尺度时间窗口与非均匀事件分布

事件时间被组织到 `1h / 24h / 7d / 30d` 四个尺度中，并采用确定性的非均匀分布：

- 高峰时间段包含明显事件突发；
- 安静区间保持稀疏；
- 不同时间范围切换时事件数和攻击链上下文存在明显差异；
- 同一核心攻击链横跨多个时间尺度，窗口外历史锚点仍可参与关联；
- 时间投影稳定可复现，不会因每次刷新而随机漂移。

这部分用于体现“以当前事件为锚点，主动向相邻窗口和长期窗口扩展检索”的项目创新。

### 4. 跨源语义和实体关系增强

领域层重新构建并完善以下对象：

- `Finding`：候选风险发现；
- `Evidence`：可回指原始日志的证据；
- `EntityProfile`：用户、主机、进程、IP、文件资产画像；
- `Investigation`：主链、候选、排除三段式案件；
- `CaseBoard`：分析员对证据阶段的人工决策状态。

系统会结合以下关系进行关联：

- 相同用户与账号；
- 相同主机；
- 进程和命令关系；
- IP 与网络连接；
- 文件、目录和资产对象；
- 多来源印证；
- 时间邻接与长程实体重叠。

实体数量、实体历史和案件证据链已恢复为完整上下文，不再只显示少量占位对象。

### 5. 综合风险评分升级

风险评分升级为 `weak_fusion_v2`。它不是单一模型概率，也不是人工标签，而是多个可解释风险信号的融合结果。

主要考虑：

- 当前事件异常程度；
- 局部窗口上下文；
- 长周期关联强度；
- 实体与关系新颖度；
- 模板稀有度；
- 多来源印证；
- 证据覆盖和关联质量。

页面会展示综合风险、分项得分和具体原因。风险分数仅作为分析排序线索，不会自动写成“已确认入侵”。发现页已移除不参与工作流的“正常”和“低危”分类，并增加综合风险排序，使分析员优先处理高风险发现。

### 6. 日志标准化展示增强

原来的“标准化事件”存在两个问题：未识别内容直接截取英文原文，执行类事件又统一退化为“进程或命令执行”。

现在拆成两层：

1. 面向分析员的中文事件摘要；
2. 面向检测链路的统一标准动作类别。

示例：

```text
SSH 会话已建立：ait（由 UID 0 发起）
sudo 权限会话已建立：root（由 ait 发起）
磁盘设备轮询未发现设备：ata1.01
采集网络指标：接口 unknown，入站 0 B，出站 0 B
创建本地用户组：gmarsh
修改用户组：将 ait 加入 sudo
DNS 解析临时失败：archive.ubuntu.com
```

原始日志没有被覆盖，仍可在详情抽屉的“原始日志”页签中核验。

### 7. 案件调查页面重构

案件页面重新调整为更适合分析工作的宽屏布局：

- 案件列表缩窄，主调查区获得更大空间；
- 攻击链图保持完整宽度；
- 主链证据和候选证据不再显示成狭长列；
- 候选证据自动使用双列布局；
- 已排除区域使用自然高度；
- 时间线、证据说明、实体枢轴和调查状态保持联动；
- 多个示例案件和上传生成案件均可独立查看。

### 8. 小影项目智能体增强

小影不再只是一个普通模型入口，而是加入了链影寻踪项目知识和确定性的案件分析能力。

当前能力包括：

- 8 篇内置项目知识文档；
- 中文关键词与项目术语混合检索；
- M0-M6、三项创新、风险评分、弱监督、无监督、评测隔离等项目知识；
- 自动、安全分析、知识问答、普通问答四种模式；
- 可配置外部模型服务；
- 外部模型不可用时使用内置安全分析引擎，不再返回空结果；
- 事实、判断、待确认、下一步核验四类结构化输出；
- 证据编号、置信度和降级项展示；
- 查看案件、打开实体、查看发现、检索日志等可执行跳转。

案件整链提交后，小影会解析阶段、时间、实体、主机、风险、摘要、证据和事件，而不是只根据 `caseId` 返回泛化建议。

以 `CASE-XLOG-30D-001` 为例，当前能够输出：

- 主链和候选阶段数量；
- 六阶段时间线；
- 重复实体和共同主机；
- 最高风险 Finding；
- `root → www-data` 主体转换缺口；
- 可回指具体 Finding ID 的下一步核验动作。

### 9. 真实数据源删除

原来的删除按钮只会暂时隐藏前端行，刷新后数据源会重新出现。

现在新增真实级联删除：

```http
DELETE /api/ingest/sources/{source_id}
```

后端会在同一事务中删除：

- 上传任务；
- 数据源记录；
- 关联事件；
- 风险发现；
- 候选案件。

系统内置事件流不提供删除按钮，用户上传的数据源可真实删除。删除逻辑已有单元测试覆盖。

### 10. 前端视觉与性能优化

前端主题调整为白色为主、蓝色为辅：

- 修复浅色背景上仍使用白色或浅色文字的问题；
- 统一卡片、表格、标签、输入框和图表配色；
- 优化聊天回答标题、列表和证据卡片的层次；
- 修复日志检索进入时的明显卡顿；
- 对 4 万级事件映射结果增加缓存；
- 控制每页展示 50 条日志，避免一次渲染全部事件；
- 图表和功能模块按需加载；
- 优化页面切换与图表动画表现。

## 五、可直接上传的样例文件

`sample_upload_logs/` 提供同一组六事件的五种格式：

```text
sample_upload_logs/
├─ wad_small_chain.log
├─ wad_small_chain.txt
├─ wad_small_chain.json
├─ wad_small_chain.jsonl
└─ wad_small_chain.csv
```

事件链包含：

```text
认证失败 → 权限上下文变化 → 编码 PowerShell → 账户创建 → 对外连接
```

每份文件约 0.5–1.6 KB，均已通过当前后端解析函数验证，每份可解析为 6 条事件。

## 八、能力边界与答辩口径

### 当前已经真实实现

- 小文件上传和后端解析；
- M0-M6 可解释原型处理；
- SQLite 持久化；
- 事件、发现、实体、证据和案件联动；
- 多时间尺度事件流和长周期攻击链展示；
- 项目知识增强的小影；
- 数据源真实级联删除；
- 小文件范围内的功能和吞吐测量。

### 当前不应直接宣称

- 不应把当前单机小文件实测描述成已经完成 TB 级生产实测；
- 不应把受控事件流中的投影分数描述成正式数据集评测结果；
- 不应把风险分数描述成入侵事实；
- 不应让真实标签参与检测或阈值调节。

### 推荐答辩表述

> 当前原型已经跑通从多格式文件接入、M0-M6 风险识别、实体关系构建、长周期攻击链关联，到智能体辅助研判的端到端链路。演示环境使用约 4.6 万条受控事件流验证交互和调查能力，并使用小文件验证真实后端处理。面向 TB 级部署时，接入层可替换为客户侧 Collector 和消息队列，计算与存储层按分区横向扩展；当前版本不把小文件吞吐外推为 TB 实测结论。

## 九、本轮更新结果概览

| 方向 | 更新前 | 更新后 |
|---|---|---|
| 文件上传 | 前端展示为主 | FastAPI 真实上传与处理 |
| 检测链路 | 部分静态结果 | 可解释 M0-M6 原型 |
| 时间分布 | 集中或过于均匀 | 多尺度、突发式、可复现 |
| 日志摘要 | 英文截断或过度概括 | 中文动作、对象和结果 |
| 风险评分 | 依据不够清晰 | `weak_fusion_v2` 分项解释 |
| 实体和案件 | 上下文较少 | 多实体、多案件、完整证据链 |
| 小影 | 泛化建议 | 项目知识 + 案件快照分析 |
| 数据源删除 | 仅前端隐藏 | 后端事务级联删除 |
| 页面主题 | 暗色和对比度问题 | 白色主调、蓝色辅助 |
| 数据入口 | 多种割裂标签 | 统一事件流产品视图 |
