# 《链影寻踪》10 分钟演示剧本 · APT 叙事版

> 主题：面向海量多源安全日志，用弱监督方法识别罕见攻击链，并把「海量日志」收敛成「少量可解释、可追溯、可执行的人工研判」。
> 本剧本以一个**新增的 APT 数据集**为主线 —— 一场跨 6 类日志源、跨 4 台主机、跨 7 天的完整 APT 攻击（侦察 → WebShell → 执行 → 持久化 → 提权 → 凭证访问 → 横向移动 → C2 → 数据渗出），用一条逻辑自洽的故事串起系统的每一个功能。

---

## 核心叙事线（一句话）

> 攻击者 `45.155.205.233` 在 7 天内，从扫描 Web 主机开始，落地 WebShell、创建后门账户 `svc_backup`、提权、爆破并横向移动到数据库主机，最终通过 DNS 隧道把数据渗出。系统把它从 7,000 多条日志里捞出来，恢复成一条 10 步攻击链，只留少量关键窗口给分析员研判。

---

## 三项核心创新（每幕落点）

| 创新 | 一句话 | 对应页面 |
|---|---|---|
| 跨源语义与实体关系建模 | Syslog / EVTX / Suricata / DNS 各说各话，先统一成同一语义空间再关联 | 总览环图 + 发现页 |
| 多尺度上下文主动检索 | 以当前事件为锚点，1h/24h/7d/30d 按需扩展，不是等量扫全量 | 总览时间范围 + 实体页 |
| 长周期攻击链关联 | 用稳定实体锚点连接跨日窗口，恢复短窗口看不到的完整链 | 案件调查页 |

**贯穿全场的价值主张**：研判压缩（海量 → 千分之一人工量）+ 可解释可追溯（每个结论都能回溯到原始日志与分层分数）。

**台词**

- "我们不做一个花哨的仪表盘，而是把『事件 → 发现 → 案件 → 证据 → 决策』这条调查闭环跑通，每一步都可解释、可追溯。"
- "今天我用一条真实的攻击故事来讲：攻击者花了 7 天，跨了 6 种日志、4 台主机，最后被我们的系统还原成一条 10 步攻击链。"

**演示动作**

- 指右上角时间范围选择器，一句带过："这是多尺度上下文的入口，一会儿会看到它怎么联动。"

## 第 1 幕 · 态势总览 + 研判漏斗（约 1:20）

**路径**：总览页

**演示动作**

1. 顶部四张统计卡：**原始事件 → 异常发现 → 进入人工研判 → 研判压缩率**。
2. 指「研判漏斗」，逐层讲 L1 事件 → L2 异常发现 → L3 系统自动处置 → L4 进入人工研判 → L5 主链证据。
3. 重点停在 L3：**绝大多数异常由系统自动研判**，只有少量高风险链落到 L4 人工。
4. 指「跨域来源分布」双层环图：外环是日志文件类型（认证 / 系统 / 网络遥测 / Windows EVTX / 入侵检测 / DNS 隧道），内环是数据集分类（Short / Long / APT）。

**台词**

- "第一个要讲的是**研判压缩**。7 天 7,000 多条日志，先收敛到几十个异常发现，其中绝大多数系统已经自动研判处置——能聚成链的聚成自动处置链，孤立的低危窗口自动归档，只有个位数的高风险候选需要人工看，压缩到千分之一。"
- "注意 L3 不是黑盒：每一条自动处置链在案件队列里都能展开，看到它由哪些异常窗口、哪些共享实体聚类而来，也能一键升级成人工案件。"
- "右边这个环图是我们第一个创新点——**跨源语义统一**。认证日志、系统日志、Windows 事件 EVTX、入侵检测 Suricata、DNS 隧道，这些日志格式完全不同、各说各话，我们先统一成语义一致的事件，才能在同一空间关联。外环就是这些跨域来源的真实构成。"

**可能的评委提问 & 应对**

- Q："研判压缩是不是把真攻击也压缩掉了？"
- A："压缩的是人工看的量，不是检测。检测层 M0-M6 是全覆盖的，只是排序后让人先看高风险。"

## 第 2 幕 · 发现页 + 风险可解释（约 1:20）

**路径**：发现页

**演示动作**

1. 右上角日志源切到 **APT**（或在全部里找 `45.155.205.233` 相关发现），按「综合风险」排序。
2. 点开一条高风险发现（如 PowerShell 编码执行 `APT-000008` 或数据渗出 `APT-000010`），展开**三层分数**：事件异常 / 局部上下文 / 长程关联。
3. 点分数，弹出 `weak_fusion_v2` 解释（36% 事件 + 29% 局部 + 35% 长程）。
4. 展示发现详情里的「M3 事件关联图」（静态居中显示）和「原始日志」证据。

**台词**

- "每一条发现都不是一个黑盒分数。我们把它拆成三层：**事件自身**有多异常、放进**局部实体关系**里还异常吗、结合**长程历史证据**又怎么判断。三个分数分开展示，评委问『这分数怎么来的』，我们点开就能回答。"
- "这条是 PowerShell 编码命令执行，来自 Windows EVTX；上面还有来自 Suricata、auth.log、DNS 的发现——它们本来语言不通，统一之后就能互相印证。"
- "M3 关联图是当前事件前 30 分钟的事实窗口：事件节点和实体节点，实线是『事件涉及实体』、虚线是『时间先后』、点线是『同一事件共同参与』，每一条边都能点开看到原始日志依据。"

**可能的评委提问 & 应对**

- Q："三层分数为什么这样分权重？"
- A："弱监督信号和模板稀有度最能刻画『像不像攻击』，权重最高；实体与长程作为辅助。关键是我们不做黑盒，每个分数都可点开看依据。"

## 第 3 幕 · 实体调查 + 多尺度基线（约 0:50）

**路径**：实体调查页

**演示动作**

1. 选中攻击者创建的后门账户 **`svc_backup`**（或攻击者 IP `45.155.205.233`）。
2. 展示**实体画像**：首末出现时间、30 天基线对比、关联主机、关联发现列表。
3. 指基线对比表的「偏离进度条」，讲"当前观察 vs 历史常态"。

**台词**

- "这是第二个创新点——**多尺度上下文主动检索 + 实体关系建模**。我们围绕『一个实体』做锚点分析：`svc_backup` 这个账户是攻击者 7 天前创建的，它第一次出现、第一次登录数据库主机、第一次回连 C2，都和它的历史基线偏离。"
- "注意一个细节：这里看的是**偏离基线**，而不是单点稀有。稀有不等于恶意——这个观点我们评测页会再呼应。"

**演示动作（加分）**

- 切右上角时间范围从 7 天 → 24 小时 → 1 小时，展示该实体的活动窗口随尺度变化，直观体现"多尺度"。

## 第 4 幕 · 案件调查 + 攻击链图（约 2:10，核心亮点）

**路径**：案件调查页

**演示动作**

1. 左侧数据集筛选切到 **APT**，打开待研判案件 **`APT-CANDIDATE-001`**（10 步基准攻击链）。
2. 指案件头卡：锚点实体、升级评分、三个方法标签（多尺度主动检索 / 长周期关联 / 跨源语义）。
3. **重点展示「攻击链路研判图」**：
   - 上方红色已确认主链窗口按时间从左到右构成单向链，下方灰色候选证据自由池（真证据 + 干扰项混合）。
   - 指攻击链图上方绿色「系统自动提取」链路条：逐阶段卡片（战术 → 技术 ID → 证据数 → 时间）、**链罕见度**、**阶段覆盖数**，与案件基准链 10 阶段对照。
4. 现场做一次研判动作：把候选证据拖进主链断口（绿色「＋」落点），或拖到「排除」区排除。
5. 切到队列「已定案」分类，展示系统自动处置链；再演示「完成研判 → 移回待研判」的双向流转。

**台词**

- "这是第三个、也是最核心的创新点——**长周期攻击链关联**。这条链跨 7 天、10 个阶段：从扫描、WebShell、创建后门账户、提权、爆破、横向移动，到 PowerShell、DNS 隧道、数据渗出。短窗口检测只能看到某一天的一两条，而我们用稳定实体（攻击者 IP、后门账户）作为锚点，把跨日的窗口重新连起来。"
- "看这条链的 ATT&CK 阶段：系统自动把它按战术聚合，覆盖了持久化、权限提升、凭证访问、横向移动、命令与控制、渗出——短时间走完整条链，本身就是一个很强的异常信号，我们把它量化成**链罕见度**。"
- "连线上不是笼统的『实体支撑』，而是具体的『同一账户 svc_backup』或『时间间隔 2 小时』，逻辑可读、可核验。"
- "这就是分析员的工作台：**系统给候选，人来拍板**。不是系统替他下结论。研判动作会实时联动到总览的数字。"

**可能的评委提问 & 应对**

- Q："自动处置会不会把真攻击也'处置'掉了？"
- A："自动处置不等于删除，案件和窗口数据都保留、可回溯；判定依据（成员、锚点、行为阶段、关联置信）全部展示，任何一条都能一键升级为人工案件。高风险链始终进入人工研判。"
- Q："链罕见度怎么算的？"
- A："由四部分加权：M2 实体稀有度 + M4 模板稀有度（这两项占 65% 权重，来自 2.2 亿行真实日志的频率标定）+ 时间压缩度 + 高风险占比。公式完整写在代码里、可复现，UI 也挂了边界声明——它是调查信号，不是入侵结论。"

**台词**

- "小影不是通用聊天机器人，而是**调查副驾**：它结合项目知识库 + 内部数据工具 + 证据核验，输出『事实 / 判断 / 待确认 / 下一步核验』四类结构化结果。"
- "它的回答必须引用内部工具证据，不是模型自由发挥；还带可执行按钮，点一下就能跳转到对应案件或实体，形成人机协同的调查闭环。"

- A："模型是**可替换的推理层**，但项目知识、检测工具、上下文和证据协议都是我们自己提供的，回答必须引用内部工具证据。"

## 第 8 幕 · 评测 + 答辩口径（约 1:00）

**路径**：评测页

**演示动作**

1. 顶部指标：PR-AUC、Recall@1%FPR、3-day Chain Recovery、EPS、Analyst Reduction。
2. 指向**消融实验**：Full System vs w/o M5 Long-term，Chain Recovery 72.6% → 41.2%。
3. 指向**错误案例分析**：`backup_admin` 在非工作时间访问 `FS-02`，但因有已批准维护工单被人工排除。
4. 指向源域对比表：1% FPR 下 Recall 更高。

**台词（收尾核心）**

- "消融实验量化了每一项创新的贡献：去掉长周期关联，攻击链恢复率直接腰斩，这就是第三个创新点的价值证明。"
- "错误案例呼应前面说的『稀有 ≠ 恶意』：`backup_admin` 非工作时间访问文件服务器确实异常，但有已批准维护工单，就由人工排除——我们的系统解释误报来源，而不是把稀有直接当成恶意。"
- "最后强调一个底线：**真实标签不进检测主流程**。系统先独立生成预测，结果落盘后评测程序才读标签算指标，杜绝标签泄漏。"
